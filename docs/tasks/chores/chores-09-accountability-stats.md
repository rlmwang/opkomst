# 09 — Per-volunteer accountability stats

**Layer:** backend + frontend · **Depends on:** 06 (shifts + actions), 04 (details page) ·
**Design refs:** §5 (Shift), §7 (actions/tick).

## Goal

On the roster details page, show for each volunteer how they've handled their turns: how
many they **completed**, **deferred** (handed off), and **missed** (let the day pass with no
response), plus how many were **assigned** to them so far. This is accountability, not
punishment — it helps organisers see who's carrying the load and who's quietly dropping it.

## The core decision: an append-only event log

The `Shift` row is mutable — a handoff nulls and reassigns `volunteer_id`, so "A deferred
this" and "A was assigned N shifts over time" **cannot be recovered** from current shift
rows. `completed`/`missed` *could* be derived from `status` + `volunteer_id`, but mixing
derived-and-logged is fragile (reassignment/deletion erase it). So log **every** outcome to
one append-only table and derive nothing:

**`ShiftEvent`** (new model, `UUIDMixin` + `TimestampMixin`):
- `roster_id` — FK `rosters.id` CASCADE, indexed (denormalised so per-roster aggregation is
  one grouped query and events die with the roster).
- `volunteer_id` — FK `volunteers.id` **CASCADE** (a volunteer who leaves takes their
  history with them — consistent with leave = full removal; the details page only shows
  current volunteers anyway).
- `shift_id` — FK `shifts.id` **SET NULL**, nullable (traceability; survives shift churn).
- `kind` — Text, CHECK in the vocabulary below.

### The event vocabulary (this is the "fourth event" question)

The three outcomes you named map to `completed` / `deferred` / `missed`. The natural fourth
is an **input** event so "assigned so far" is meaningful and self-pickups are visible:

| kind | emitted when | shown as |
|---|---|---|
| `assigned` | the tick auto-assigns a volunteer to an open shift | part of "assigned" total |
| `claimed` | a volunteer takes an open/up-for-grabs shift themselves | part of "assigned" total (self-pickup) |
| `completed` | volunteer marks a shift done | "done" |
| `deferred` | volunteer hands a shift off ("can't make it") | "handed off" |
| `missed` | a still-`scheduled` past shift they held flips to `missed` on the tick | "missed" |

"Assigned so far" = `assigned` + `claimed` (every shift they became responsible for).
`completed + deferred + missed` are the resolved outcomes; the remainder is still upcoming.

*(Confirm the taxonomy — if you'd rather not distinguish `claimed` from `assigned`, collapse
them into one `assigned` kind and drop the fourth. Everything else stays.)*

## Deliverables

1. **Model + migration** — `backend/models/chores.py` gains `ShiftEvent`; register in
   `models/__init__.py`; one autogenerated Alembic migration (idempotent under the CI
   downgrade/upgrade check). No backfill — pre-launch, stats accrue from launch (note it).

2. **Emit events** (one insert at each site; keep them in the existing handlers/services):
   - `chore_tick._assign` → `assigned` for each auto-assignment.
   - `chore_tick.reassign_shift` (handoff's re-assign) → `assigned` for the new holder.
   - `chore_tick` reconcile (`scheduled → missed`) → `missed` for the assignee. **This is
     currently a bulk `UPDATE`** — switch to selecting the affected `(shift, volunteer_id)`
     rows first so an event can be written per shift, then update.
   - `routers/chores_public.py`: `claim` → `claimed`; `done` → `completed`; `handoff` →
     `deferred` (for the bailer, before reopening).

3. **Aggregation** — `services/chores.py`: one grouped query
   (`volunteer_id, kind → count`) per roster; fold into `VolunteerSummaryOut`. Extend that
   schema with `assigned`, `completed`, `deferred`, `missed` (keep `load` = current
   upcoming). `claimed` folds into `assigned` for display, or expose it too — your call.
   Still **no email/ciphertext/token** in the projection (the leak-guard test must stay
   green).

4. **`make openapi`** + frontend types.

5. **Details page** — `ChoresDetailsPage.vue` volunteers card: per volunteer show the
   assigned total + a compact done / handed-off / missed breakdown (chips or a small table).
   nl + en i18n, locked-step.

## Tests

- **`tests/test_shift_events.py`** — each action/tick path writes the right event kind;
  aggregation returns correct per-volunteer counts; a handed-off shift records `deferred`
  for A and `assigned` for B; a missed shift records `missed` for the holder.
- Extend the volunteer-list leak guard: the new count fields are present, still no
  email/ciphertext/token.
- `test_chore_tick` reconcile test updated for the per-shift missed events.

## Acceptance

- `uv run pytest --no-cov` green; `make openapi` no diff; `uv run ruff check backend tests`
  clean; `npm run test` + `npx vue-tsc --noEmit` green; migration idempotent.

## Out of scope

Per-chore breakdowns, streaks/leaderboards, exporting stats — later if wanted. No
notifications or enforcement (this is display-only).
